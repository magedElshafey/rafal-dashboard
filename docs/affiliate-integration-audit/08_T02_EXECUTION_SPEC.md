## Transport contract and acceptance

Use `$http` with relative `/dashboard/...` paths. A base ending `/api/v1` plus `/dashboard/affiliate-settings` must resolve to exactly `/api/v1/dashboard/affiliate-settings`, including a trailing-slash base variant. Do not append `/api/v1` inside feature services or copy a deployed host. The host in `.env.example` is not authorized staging.

The shared request interceptor reads the current staff session at dispatch (`src/config/axios.helpers.ts:10`). Affiliate code must not read localStorage, construct Authorization or reuse an Affiliate Panel token. Existing login remains multipart POST `/dashboard/auth/login` (`src/modules/auth/service/login.service.ts:4`). Persisted staff-session behavior is preserved, with no second token owner and no new secret logs.

Accept remains `application/json`; JSON mutation bodies use existing `$http` behavior. Add `X-Locale: ar|en` through the header owner (guide p.1, inherited). Normalize locale tags such as ar-SA/en-US to their supported base language, falling back to the configured supported locale, then ar if no supported locale is available. This fallback is a frontend design choice, not a claim about undocumented Backend behavior. Preserve existing locale headers for other consumers and ensure supported-language consistency. Read locale at request time so a language change affects the next request.

Pass TanStack's AbortSignal through each service into `$http`. Aborted requests produce no user error toast. Preserve response rejection and existing suppression flags; feature-owned feedback must have one notification owner.

401 behavior remains centralized: only a response whose Authorization matches the current authenticated staff token clears cache/session and redirects to Login. An old-session 401 must not log out a new session; failed login without matching auth must not loop. Source: `src/config/axios.ts:27`. 403 preserves the session; default redirect remains `/403`, while an explicitly opted-in feature may render a local forbidden state using `suppressForbiddenRedirect` (line 43). Do not globally change this behavior or turn 403 into success.

## Effective permissions and feature gating

There is **no confirmed effective-grants source**. The login type has roles only and normalization copies only identity/roles. It cannot prove what extra fields the live response contains. `/dashboard/permissions` is an assignable catalog, and `/dashboard/admins/{id}` models roles, not effective grants. Local auth notes say no `/me`/refresh endpoint; this is secondary documentation, not new Backend verification.

Prepare a pure capability policy receiving an explicit unknown-or-confirmed grants state. Unknown, malformed, expired or unavailable grants deny access. An explicitly confirmed empty grant set also denies. Match exact names, with no role-name/Super Admin bypass, wildcard inference or M⇒V assumption. Source hydration, refresh triggers and expiry depend on Q01. Do not invent polling, refresh endpoints or persist a grants snapshot as indefinitely authoritative.

## Envelopes, field errors and safe feedback

The inherited guide p.1 establishes `{success,message,data,meta?}` and failure `{success:false,message,errors}`. Validate the consumed envelope, then use separate slice-specific schemas when their contracts are known. Never treat `success:false` as successful data or turn malformed envelopes into empty lists/success messages. Allow additive fields while enforcing required consumed fields; do not fabricate balances or make all unknown fields nullable.

For opted-in Affiliate operations, preserve a nonempty Backend string `message` and mapped Laravel 422 string-array messages. Use a narrowly scoped extension/helper so existing generic defaults in `src/config/axios.helpers.ts:34` and shared form callers remain stable. Reuse snake_case/bracket/dotted alias resolution in `src/utils/apply-api-validation-errors.ts:10`; whitelist actual form fields and report unmapped errors at form level. Do not cast arbitrary server keys into trusted field paths. Existing callers must not gain different behavior implicitly.

Render Backend text through normal React text nodes/toasts, including `sms_message` in later slices. Never pass it to HTML parsers, `dangerouslySetInnerHTML`, Markdown HTML rendering or raw JSON/config diagnostics. Network/malformed/unexpected failures use existing localized fallback keys in EN/AR. Cancellation is silent. Assign success/error ownership once with the existing suppression flags to prevent duplicate global and local notifications. Do not expose credentials, stack traces, request configs or generated passwords.

## Query and cache safety

Use the central TanStack QueryClient and existing feature key namespace. Shareable search/status/date ranges belong in URL parameters and matching query keys. Existing Affiliate reads already set `retry:false` (`src/modules/affiliates/hooks/useAffiliates.ts:8`, `src/modules/affiliates/hooks/useAffiliate.ts:7`, `src/modules/affiliates/hooks/useAffiliateSettings.ts:6`); do not repeat the audit's broad suggestion that they necessarily inherit three retries. Preserve no automatic retries for writes, 401/403/422, or terminal decision conflicts.

`clearQueryClientAtAuthBoundary` synchronously advances the epoch, cancels queries and clears caches; running mutations cannot be cancelled by this alone. Capture the epoch at mutation dispatch, compare it before every cache write/invalidation and user-facing completion, including after awaited invalidations. Suppress stale-session success/error callbacks and protected-data reintroduction; allow necessary local cleanup. Reuse the owner rather than adding another global epoch/store/listener. Protect grant revision changes too once Q01 defines refresh semantics.

Preserve existing boundary entry points: `src/modules/auth/hooks/useLogout.ts:9`, `src/modules/auth/components/AuthStorageSync.tsx:21`, and the shared 401 handler. Cross-tab identity/token changes clear caches. Direct store logout currently only clears auth storage/state (`src/store/auth.ts:106`); do not assume it independently clears QueryClient. Tests must exercise actual supported entry points and prove old responses cannot populate the next identity's cache.

Within one session, cancel in-flight reads before authoritative replacement so older GETs cannot overwrite mutation success. Serialize conflicting submissions, retain duplicate-submit locks, and reject stale completion writes. Only complete verified resources can replace detail caches; partial profile/status results must not erase finances, periods or nested collections. Narrowly invalidate affected list/detail variants when authoritative data is absent. Never reload the page to reconcile a mutation, recompute financial totals, invalidate all Dashboard data, or call the unsupported activity endpoint.
